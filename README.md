# ky-app

現場作業員向けのスマホ業務アプリ（試作）。今はKY（危険予知）の入力画面と、工事指示書をQRコードで受け取る仕組みがあります。

- `index.html` … KY入力画面（スマホ用）
- `rules.json` … KYのルール（作業種別と危険度、作業前確認事項、リスク見積の呼び名、参考例）。文言や危険度はここを直せば画面に反映される
- `qr.html` … 工事指示書のQRコードと、Teams送信先の登録QRを作るページ（事務所のPC用）
- `qr-excel.md` … 工事指示書と日報のExcelに「QR用」セルを作る方法

## このリポジトリは公開されています

誰でも中身と履歴を見られます。**業務情報は入れないでください。**

入れてはいけないもの（例）：

- 社名・営業所名・個人名・社員名簿
- 顧客名・現場名・案件の実データ
- 単価・原価・金額・見積や請求の内容
- 社内のExcel・PDF・写真、社内資料
- パスワード・アクセスキー、個人や会社のメールアドレス
- Teamsのチャネルのリンク（会社やチームを特定できる番号が入っている）

見本のデータは「テストビル」「B-1234」のような作り物にしてください。

## Teamsへの送信

確認画面の「Teamsに送る」で、KYの内容をコピーしてTeamsのチャネルを開きます（貼り付けて送信するのは人の操作）。送信先のチャネルはコードに書かず、`qr.html` で作った登録QRをスマホで一度読んで、そのスマホの中に保存します。

## コミットのアドレス

コミットには GitHub の非公開アドレス（`…@users.noreply.github.com`）を使います。個人や会社のメールアドレスは使いません。

## 入力の引き継ぎと自動保存

サーバーやデータベースは使いません。入力内容を外部へ送る処理もありません。

- **自動保存**：入力のたびに、その端末のブラウザの中（localStorage）に保存します。開き直すと続きから入力できます。作業日は開いた日の日付になり、天気・作業前確認事項・「お客様指定の用紙」は同じ日に開き直したときだけ戻ります。「入力をクリア」で消せます。
- **スマホに送る**：入力内容を圧縮して、リンクの `#` より後ろに入れます（`#` より後ろはサーバーに送られません。`?` には入れません）。QRコードか「リンクをコピー」でスマホに渡します。リンクが858文字を超えるとQRが細かくなりすぎるため、QRは出さずコピーだけにします。作業日・天気・作業前確認事項・「お客様指定の用紙」は引き継ぎません。
- リンクで開いた内容は、端末に保存してあった入力より優先されます。受注番号が違う案件を取り込んだときは、前の案件の入力を消してから取り込みます。
- `qrcode.js` … QRコードを描く部品（QR Code Generator for JavaScript、MITライセンス）。CDNは使わず、このリポジトリの中に置いています。

共用のPCで入力した場合は、送ったあとに「入力をクリア」を押してください（次に開いた人に内容が見えます）。
